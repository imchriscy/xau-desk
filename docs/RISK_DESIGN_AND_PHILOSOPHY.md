# XauDesk · 风控设计与交易哲学

> 项目路径：`win-trade-terminal/`（Windows 本地 · MT5 网关 + 自建前端，避免在 MT5 终端情绪化直连下单）

文档记录产品目标、已实现的规则，以及交易员对「小资金高倍增长 vs 人性弱点」的自述（2026-11-03）。

---

## 1. 为什么要自建 APP

- **盘感与实战**：多次小资金实盘高倍经历（例如 40U→1000U→7000U，或 100U→600U→10000U 等路径），策略与执行有实战基础。
- **真正短板**：不是信号本身，而是 **风控纪律** 与 **情绪化连续开单**，容易导致大回撤或爆仓。
- **产品定位**：用代码做「严格的技术性约束」，把人性弱点关进笼子里；成熟心性下 **不在 MT5 上直接操盘**，统一经本 APP 下单（网关校验 + 锁定 ARM）。

---

## 2. 小资金数学直觉（100 USD 示例）

- 单笔止损约 **2 USD**，止盈目标约 **4.54 USD**，胜率约 **45%** 时，大数定律下期望可为正。
- 因此需要：**笔笔带止损**、**单笔亏损上限**、**日内总回撤上限**，避免少数极端连亏拖垮账户。
- 小资金可接受 **更宽的日回撤**（换更高日收益波动），例如净值 **25%～30%** 日损上限；资金变大后日损比例应 **收紧**（如约 **10%**）。
- 100 USD、**2%** 单笔止损 ≈ 2 USD/笔；**25%** 日风控 ≈ 25 USD，约等于 **13～15 笔** 满止损才触日顶——在 45% 胜率下概率很低，但仍保留日风控兜底。

## 3. 已实现风控池（网关 `backend/risk_engine.py` · v0.4+）

### 3.1 日风控（北京 06:00～次日 05:00 为同一交易窗）

- 锁定 **基准净值**（本窗内不可随意改基准解除暂停）。
- **单笔最大亏损**：USD 和/或 净值 %，取更严。
- **当日累计亏损上限**：USD 和/或 净值 %，取更严。
- 触发后：**暂停至次交易日 06:00（北京）**，并尝试 **平掉持仓、撤挂单**（一次性 token 防重复 flatten）。
- 本窗内 **参数锁定**（防盘中改规则）；暂停中 **禁止改参数/改基准**。

**锁定 persistence（重要）**

- 同一 MT5 **登录号** 隔离状态（`risk_state.json` → `accounts/<login>`）。
- **不再** 因净值相对基准大幅下跌而自动清空风控（旧逻辑会导致「触发日风控后净值变化 → 风控消失」）。
- 仅当 `bound_login` 与当前 MT5 登录不一致时重置桶（防串账户）。

**净值分档建议（UI 一键填入）**

| 净值（约） | 建议单笔 % | 建议日损 % |
|-----------|-----------|-----------|
| ≤ 500 USD | 2%        | 25%       |
| ≤ 2000 USD| 1.5%      | 20%       |
| 更大      | 1%        | 10%       |

### 3.2 头寸与 APP magic（v0.4.1+）

- **仅允许 APP magic**（`8805190`）：若 MT5 上仍有非本 APP 的持仓/挂单，**拒绝新开单**。
- **持仓 + 挂单 ≤ 6**（仅计 APP magic）。
- **保证金总上限**：`演算本金 × 200 ÷ MT5 杠杆`（例：演算 100U、杠杆 1000 → 上限 20U 保证金 ≈ 0.05 手量级；演算 1000U、杠杆 100 → 约 2000U 保证金预算）。
- **演算本金 `virtual_equity_usd`**：大账户（如 12 万 USD）可按 **1000 USD** 做严格风控；日损与单笔止损按演算本金/锚定净值跟踪，**与登录号绑定**，触发后时间锁不因净值变化解除。

### 3.3 连续止损暂停（常开 · 本品种全部平仓）

- 统计本交易窗内 **XAU 品种全部平仓 deal**（与「仅 APP magic 可下单」独立）。
- **止损触发**与 **手动平仓亏损** 均计入连续亏损；盈利平仓则清零计数。
- 每笔亏损写入 `streak_loss_counted` 审计（标注 sl / manual / 等）。
- 原则：尽量少手动平仓，以免破坏执行一致性；若手动亏平，风控仍一视同仁。
- 本地 **`trade_journal.json`** 记录已处理 deal + APP 侧平仓事件，与 MT5 历史 **双轨核对**。
- 规则：
  - **连续亏损 3 笔**（盈利 &gt; 0 则计数清零）：暂停 **30 分钟**。
  - **连续亏损 5 笔**：暂停 **3 小时**，并将连续计数 **清零**（之后需重新累计 3 笔才再触发 30 分钟档）。
  - 30 分钟档在本轮连亏中 **只触发一次**（直到赢单或 5 笔档重置）。
- 暂停时长从 **触发时刻** 起算（网关以 PC 北京时间为准）；若 MT5 deal 时间戳比 PC 快，不会用「未来成交时刻 + 3h」拉长倒计时。
- 与日风控并行时，**取更晚的解锁时间**。

### 3.4 强制止损（SL）

- 默认 **无 SL 不允许下单**（可通过风控面板关闭，不建议）。

## 4. 状态文件

| 文件 | 用途 |
|------|------|
| `backend/risk_state.json` | 每账户配置 + 运行时（暂停截止、连续止损计数等） |
| `backend/trade_journal.json` | 平仓 deal 去重与审计日志 |
| `backend/risk_events.jsonl` | 风控触发闭环日志（BJT 时间戳 + SHA256 哈希链，防篡改校验） |

**设置 → 查看风控日志**：只读展示、完整性校验、系统/网关异常（`login=0`）。

修改后端后请 **`restart-backend.cmd`**，网关版本应为 **`0.4.1-risk-exposure-log`** 及以上。

### 当前实盘计划（示例 · 12 万盘按 1000 演算）

- 演算本金 **1000 USD**，单笔止损 **20 USD**，日损上限 **250 USD**（25%），单笔约 **0.1 手**，止盈约 **45.4 USD**（待统计胜率）。
- 风控面板一键：**「严格模板 · 演算 1000U（20/250）」** → 保存并 **锁定基准** 后当日参数锁定；事件见 `risk_events.jsonl` 与风控面板列表。

## 5. 还可考虑的风控层（尚未全部实现）

在「日风控 + 连续止损 + 强制 SL」之上，可按优先级逐步加：

1. **同时持仓 / 挂单数量上限**（防情绪化叠单）。
2. **单位时间最大成交笔数**（如 15 分钟内最多 N 笔）。
3. **最大手数 / 最大名义敞口**（随净值阶梯变化）。
4. **盈利回撤锁利**（如当日浮盈回撤超过峰值 50% 则停手）。
5. **距上次平仓冷却 X 秒** 才能再 ARM（防 revenge trade）。
6. **仅允许 APP magic 单**（可选硬模式；当前为「全账户 XAU 平仓计入连损」更严）。
7. **日盈利封顶停手**（小资金可设「达 +30% 收工」保护利润）。
8. **异常滑点 / 无止损持仓监控**（发现 SL 被删则告警或强平）。

## 6. 交易员自述摘要（原文主题）

> 个人有过实盘百倍小资金多次经历，盘感与执行自信，但弱点是风控与情绪化，导致巨大回撤或爆仓。路线常是 40U→1000U→7000U 或 100U→600U→10000U，却难以长期持有利润。长久之计必须是：**控回撤、禁重仓、笔笔止损**。因此开发 **不直接在 MT5 情绪化下单** 的 Windows XAUUSD 操盘 APP，用工程化风控约束人性。
